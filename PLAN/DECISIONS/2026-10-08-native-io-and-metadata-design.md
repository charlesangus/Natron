# Native Read/Write and native metadata design

Decided 2026-10-08 with the user. Native Read and Write replace the container nodes under the same plugin IDs, as M67 did for the core nodes, and use OpenImageIO (already linked by `Engine`) for EXR, PNG, JPEG and TIFF. Video and RAW formats stay on the OFX openfx-io plugins through a fallback in node creation. Metadata becomes a host-side per-frame key/value map that travels through native nodes and is bridged to the OFX clip metadata at the boundary; this replaces the current behaviour where metadata stops at a native node. The large-image Write bug (int `(height - 1) * rowBytes` overflow in the OFX `WriteOIIO`) is not patched in the OFX plugin: the native writer fixes it by using 64-bit addressing and has a gate test over 2^31 bytes. No backward-compat loaders for old Read/Write projects.
