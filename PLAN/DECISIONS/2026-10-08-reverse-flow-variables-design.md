# Reverse-Flow Variables: design

Decided 2026-10-08 with the user. Reverse-Flow Variables (RFVs) are Nuke "graph-scope variables" generalised: any knob-typed value, animatable, set on the project or by a `ReverseFlowVariableSet` node, read in knob expressions through a Python `rfv` object.

- **Per-path semantics.** An upstream node sees the variables of the nearest downstream Set node on the path that requested it. If the same node is reached through two Set nodes in one render (a diamond), it renders once per distinct context. Chosen over one-context-per-render because the user's SetGraphVar1/SetGraphVar2 example needs it and a diamond must not be an error.
- **Declaration.** A new RFV flag on the group knob. Every child of an RFV group is one variable; its script name is the variable name. Only the Set node and the project settings carry an RFV group, so plain user knobs never become RFVs and a variable setter is always recognisable. Rejected: a dedicated typed list (rebuilds animation, arrays and serialization) and a per-knob flag (any node could silently set variables).
- **Resolution time.** A Set node's values and the project's values are evaluated at the time the request passes through the Set node (the project's, at the render root's time), then frozen into the context that flows upstream. An upstream TimeOffset does not re-evaluate them.
- **Nesting.** A Set knob's own expression may read `rfv`; it sees the context from further downstream than itself. Project values are the base layer.
- **Unset reads.** `rfv.name` and `rfv('name')` return `None` when the variable is unset, so expressions can test for it.
- **Cache keying.** Each node's context key is the hash of only the variables in its upstream read-set (variables named in expressions on the node or anything it depends on), found by scanning expression text. A dynamic access (`getattr(rfv, ...)`, a computed name) marks the node as reading everything. Nodes that read no RFV collapse to one context, so they share caches exactly as today. The key is folded into the render node hash, which feeds `ImageKey`, `ActionsCache`, `DeepImageKey`, the viewer texture cache and the scheduler's keys. The expression result cache `_exprRes` is bypassed for expressions that read RFVs.
- **Outside a render** (parameter panel, `instanceChanged`) `rfv` returns the project's base values at the timeline frame.
- **Not supported in v1:** metadata that depends on an RFV (format, frame range, layers). It is cached per node, so it uses the base values. Group nodes carry no RFVs and there is no global listing panel (user scope cut).
