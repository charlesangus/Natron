# GUI bench gate rule

Decided 2026-10-13 by the user, while planning M117 - GUI Perf Harness And Baseline and M118 - Large Graph GUI Responsiveness. GUI performance regressions are caught with local timings only, and there is no CI timing gate, because GitHub runners are too noisy for wall-clock numbers. From M117 on, every milestone whose diff touches the node graph (`Gui/NodeGraph*`, `Gui/NodeGui*`, `Gui/Edge*`), knob expressions (`Engine/Knob*`) or node naming (`Engine/NodeGroup*`) runs `tools/bench/gui/run.sh --xvfb` at its verification gate. It compares the run against the committed Xvfb baseline with `compare.py`, and records the result. A flagged regression blocks the gate unless the user accepts it. Xvfb numbers in the dev container are directionally right but much slower than a real display, so they're used only for regressions. Performance budgets (16 ms or less per interaction event, 100 ms or less per edit, no stall over 250 ms, and linear bulk operations at 3000 nodes) are judged on the real host the user tests on. Only the compare script's deterministic self-test runs in CI.
