# USD nodes are named USD<Whatever>; native geometry nodes Geo<Whatever>

Every node in the USD/3D system (E9 - USD And 3D) that authors or consumes USD scene data is named `USD<Whatever>`, the same prefix convention the deep nodes (`DeepRead`, `DeepMerge`, `DeepToImage`) and raw nodes (`Raw<Whatever>`) use. Native geometry (M54 - SOPs-Style Geometry's `GeoDetail` data) is its own kind and keeps `Geo<Whatever>`, and the bridges between the two are named the way `DeepToImage` is. The user set both rules on 2026-10-24 while grilling M19 - USD/Hydra Foundation. They apply to plug-in IDs, labels, class names and source file names.

The renames were applied the same day in the files of M19 - USD/Hydra Foundation, M20 - 3D Node Vocabulary, M21 - Deep Tier-2 And Bridges, M52 - USD Layer-Stack Completion, M53 - Projected Texture Painting and M54 - SOPs-Style Geometry: `ReadScene`→`USDRead`, `WriteScene`→`USDWrite`, `HydraRender`→`USDRender`, `Camera3D`→`USDCamera`, `Light3D`→`USDLight`, `Material3D`→`USDMaterial`, `Merge3D`→`USDMerge`, `Prune3D`→`USDPrune`, `Prim3D`→`USDPrim`, `Transform3D`→`USDTransform`, `EditPrim3D`→`USDEditPrim`, `SetAttribute3D`→`USDSetAttribute`, `Reference3D`→`USDReference`, `Variant3D`→`USDVariant`, `GeoToScene`→`GeoToUSD`, `SceneToGeo`→`USDToGeo`. The design docs under `PLAN/DESIGN/` keep the old names as history.
The same pass replaced every mention of the standalone `Viewport3D` panel in those files with the unified Viewer's 3D view (widget `Gui/SceneViewport`), per M19 - USD/Hydra Foundation's one-Viewer decision. M54 - SOPs-Style Geometry's geometry display now extends the Viewer's kind-driven switch to the geometry kind, and M20 - 3D Node Vocabulary's `USDRender` shares the GUI's 4.5 compatibility context, or creates its own offscreen context when headless.
