# M45 and M46: open questions (2026-10-11)

Questions from elaborating M45 - Native Tab Menu and M46 - Labelmaker Annotations. Each has options and a recommended default.

## M45 - Native Tab Menu

### Q1. What "smart insertion onto the pipe" means

tabtabtab itself has no such feature.
- (a) Keep only today's insert-after-the-selected-node.
- (b) **Recommended:** also, when nothing is selected, splice into the pipe under the cursor (P3.T1), using M55's splice and undo code.
- (c) Also splice when a node is selected and the cursor is on a pipe, with the pipe winning.

### Q2. Whether the palette searches menu commands

This is tabtabtab's headline feature.
- (a) **Recommended:** yes, the main menu bar only (P3.T2).
- (b) Also the node graph's right-click menu.
- (c) Nodes only, and drop P3.T2.

### Q3. Tab menu preferences

- (a) **Recommended:** none for now. The search modes keep tabtabtab's defaults, and P1.T1 takes the mapping as a parameter so it can be added later without touching the matcher.
- (b) Port tabtabtab's preferences now (mode remap and scroll toggle), which also means editing `Engine/Settings.*`.

### Q4. A fallback to the old menu

tabtabtab keeps Nuke's menu on Ctrl+Tab.
- **Recommended:** no fallback. The old dialog is deleted (P2.T3).

### Q5. Generator rows coloured by grouping

A plugin-level category can't detect generators without an instance, so the menu may colour a few generators by their grouping instead.
- **Recommended:** accept that. The alternative is a cached probe instance per plugin, which is slow on startup.

### Q6. The M69 "Tab menu position" item

- **Recommended:** M45 takes it over. Strike the item from M69 and point it at M45.P2.T1.
- Alternative, if you want the jump gone before M45 runs: M69 does a two-line fix (block signals around `setText` in the `NodeCreationDialog` constructor, or return early from `filterText` while the dialog is hidden). M45 then deletes that code anyway.

## M46 - Labelmaker Annotations

### Q1. Licence of the translated base config (please confirm)

Labelmaker is GPL-3.0 and Natron is GPL-2.0-or-later. M46 is a clean C++ reimplementation, but P1.T4 translates `base_config.json`, which is data from a GPL-3 project. If you wrote Labelmaker, which the `charlesangus` handle suggests, this is moot.
- **Recommended:** confirm you're the author and are fine relicensing the config under Natron's licence.

### Q2. What replaces TCL in config lines

- (a) **Recommended:** `{knob}` / `{knob.N}` templates (P1.T2). Cheap, safe and testable.
- (b) Python expressions per line. Very flexible, but each refresh takes the GIL and is slow on big graphs.
- (c) Both, with Python only as an opt-in key.

### Q3. The config editor

Labelmaker has an 812-line GUI editor with layer forking.
- (a) **Recommended:** not in M46. Ship JSON files, live reload and the "Reload Node Annotations" action, and stub a follow-up milestone for the editor.
- (b) Add a Phase 46.6 for the editor, which is about L+L.

### Q4. Auto de-overlap when a label grows

- (a) **Recommended:** ship only the undoable "De-overlap All" now (P4.T2).
- (b) Also auto-push, on by default as in Labelmaker, but as an undoable move command. That means a Ctrl+Z after a knob edit may undo the push first.
- (c) Auto-push off the undo stack, as Labelmaker does. Not recommended: Natron's move commands store absolute positions, so later undos would fight the hidden moves.

### Q5. Whether the channel summary line replaces or joins today's layer summary

- **Recommended:** replace it when annotations are on (P3.T2), and keep today's exact behaviour when they are off.

### Q6. Where the personal config lives

- **Recommended:** `QStandardPaths::AppConfigLocation/node_annotations.json`, i.e. `~/.config/<org>/Natron/`.
- Alternative: next to the user's PyPlugs path.
