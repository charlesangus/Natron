# Milestone 39: Adopt "layer" terminology instead of "planes"

Natron's UI, Python API and docs already say "layer" (ImageLayer, NewLayerDialog, getAvailableLayers, kNodeParamProcessAllLayers) while the engine, serialization and a handful of user-visible strings still say "plane" — 98 distinct identifiers, ~1,500 occurrences across 109 files (`ImagePlaneDesc` alone is 736 occurrences / 93 files). This milestone is a full rename, Tiers A+B+C: user-facing strings, internal C++ identifiers, Python API names, the `processAllPlanes` knob script-name and the `PlaneID`/`PlaneLabel` serialization tags. No compatibility shims, no deprecated aliases, no load-time renames: this fork is a clean break from earlier Natron projects and PyPlugs. What stays "plane" is exactly the OpenFX boundary, because those are identifiers plug-ins pass across the ABI: everything in `libs/OpenFX/include/nuke/fnOfxExtensions.h` and `libs/OpenFX/include/ofxNatron.h` (`kFnOfxImagePlane*`, `kOfxImageEffectPropRenderPlanes`, `kNatronOfxImageComponentsPlane*`, `kNatronOfxExtraCreatedPlanes`), the HostSupport virtuals `ClipInstance::getImagePlane()` and `ImageEffect::Instance::getUserCreatedPlanes()` (declared in the `libs/OpenFX` submodule, overridden in `Engine/OfxClipInstance.h` and `Engine/OfxImageEffectInstance.h`), the OFX choice values such as `uk.co.thefoundry.OfxImagePlaneColour.R` (also the only "plane" strings in `Gui/Resources/PyPlugs/*.py`), and the OFX-facing half of the bridging converters. Natron-side macro *names* (`kNatronColorPlaneID` etc., `Engine/ImagePlaneDesc.h:55-68`) are renamed; their *values* are not. Excluded as unrelated: `Global/glad*` GL clip planes, `Global/StrUtils.cpp` Unicode planes, `Gui/ViewerGLPrivate.cpp` wipe `rightPlane` geometry, `RotoLayer`/`kRotoLayerBaseName`, and comments quoting the OFX spec's geometric "image plane".

Build/test commands used by every task below (single-tenant container, never two builds at once): `tools/ci/local/build.sh debug` (add `--reconfigure` after any file rename — `Engine/CMakeLists.txt` GLOBs `*.cpp`/`*.h`, so no list edit is needed but the cache must be regenerated), `tools/ci/local/test.sh ctest debug`, `tools/ci/local/test.sh smoke debug`. Format gate (the `format` job in `.github/workflows/checks.yml`, run locally): `pip install --user --break-system-packages clang-format==21.1.8` once, then `git clang-format --binary "$(python3 -c 'import clang_format,os;print(os.path.join(os.path.dirname(clang_format.__file__),"data","bin","clang-format"))')" --extensions c,cc,cpp,h,hpp,mm --diff "$(git merge-base origin/main HEAD)"` must exit 0 (`lint-ci` is shellcheck/actionlint only and is unaffected). "plane"/"layer" are the same length, so `Plane→Layer`, `plane→layer`, `PLANE→LAYER` token swaps preserve `AlignAfterOpenBracket: Align` continuation alignment; the only different-length rename (`ImagePlaneDescEnum→ImageComponentsEnum`) needs manual re-alignment at `Engine/Image.cpp:1666-1667`.

## Decisions
- 2026-09-18 — Scope is Tiers A+B+C (user strings, C++ identifiers, Python API, knob script-name, XML tags): the user chose a full rename; partial renames leave two vocabularies for the same concept, which is the confusion this milestone removes.
