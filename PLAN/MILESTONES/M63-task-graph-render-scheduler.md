# Milestone 63: Task-graph render scheduler

> **Elaborated 2026-10-04** (planning consultant, fable; clean run per the user's direction recorded under `## Decisions`). Architecture: a task graph built from the request pass, executed on the one global pool, with `renderRoI` as the task body. Decision draft: `DECISIONS/2026-10-04-task-graph-render-scheduler.md` (published at P6.T1).

Replaces the recursive pull-per-node execution of a frame with a scheduled task graph while keeping `renderRoI` as the unit of work. The request pass that already enumerates every (node, time, view) a frame needs is extended to record edges; a per-frame `FrameRenderContext` carries the frame args, request map, abort info and a `FrameStore` of produced images; an app-wide `RenderScheduler` runs ready node tasks on the one global `QThreadPool`, shared with the OFX multithread suite and host frame threading, ordered depth-first within a frame and frame-major across frames so independent branches and consecutive frames overlap with bounded intermediates. Cache rules, trimap, render-safety locks, identity and transform handling are unchanged because they stay inside `renderRoI`. A `renderSchedulerMode` setting keeps the legacy path so every render suite is checked both ways for bit-identical pixels. Writers first, viewer last; deep subtrees, OpenGL, roto strokes and analysis renders stay pull-inside-a-task in v1. Targets are stated in scaling terms (occupancy ≥0.8·P of the pool, frame time ≤0.8× where the graph's parallelism allows); the 4-core host gives the first data points only.
