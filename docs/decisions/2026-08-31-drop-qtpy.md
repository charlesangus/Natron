# 2026-08-31 — Drop qtpy; the build depends on the ASWF container and nothing else

Natron imports `qtpy` at startup (`Engine/AppManager.cpp:1806-1828`) and lists
it as an install requirement (`INSTALL_LINUX.md:110`). Upstream adopted it
deliberately (CHANGELOG, #687) as an abstraction over PyQt4/5/PySide/PySide2 so
that user scripts stay portable across Qt versions.

**That rationale does not survive this fork.** The fork targets exactly one Qt
(6.8) and one Python (3.13), and has already deleted Qt5 rather than guarding
against it. An abstraction layer whose entire purpose is to hide which Qt
binding you have buys nothing when there is only ever one, and its absence from
`aswf/ci-baseqt:2027.0` made it a new external dependency: `M2.P3.T1d` added a
`pip install` to satisfy it, which contradicts the standing requirement that
the build need only the ASWF container (see
`2026-08-29-target-vfx-cy2027.md` and `2026-08-30-sealed-package-network.md`,
which chose to use the image as-is rather than reconstruct package steps).

**Decision: remove `qtpy` entirely.** Natron imports `PySide6` directly, which
ships in the image (verified 2026-08-31: PySide6 6.8.3 with `QtCore`/`QtGui`,
plus `shiboken6`, at `/usr/local/lib/python3.13/site-packages`). `M2.P3.T1d`'s
install plumbing is reverted with it — no `pip install` in CI or the local
loop, and the container returns to being used as-is.

`QT_API=pyside6` (`AppManager.cpp:2924`) goes too: it exists solely so qtpy
resolves to PySide6, and has no other reader. The bug it was guarding against
(#854 — qtpy handing user scripts PySide2 enum semantics under a PySide6
runtime) cannot occur once nothing consults qtpy.

**Accepted cost, stated plainly:** this is a breaking change to the public
scripting API. Third-party PyPlugs and user scripts written as
`from qtpy import QtCore` will fail and must become
`from PySide6 import QtCore`. That is a real break for existing users, taken
knowingly: it is the same trade this fork already made in dropping Qt5,
Windows and macOS, and the alternative is carrying a dependency and an
indirection permanently to serve a portability guarantee the fork does not
offer.
