# rgba, rgb, alpha and xy replace the Color layer

2026-09-26. User decision, via /cat-plan. The single user-visible "Color" layer is replaced by four built-in registry layers, each with its own ID: `rgba`, `rgb`, `alpha` and `xy`. They replace Color in every menu, in the channel-set, layer-select and channel-select knobs, in Shuffle, in the viewer, in Python and in project files.

They are views of one stored colour plane and share its channels, so `rgb.R` *is* `rgba.R`. The storage/OFX ID `kFnOfxImagePlaneColour` stays internal. OFX maps by component count: 4 ⇄ rgba, 3 ⇄ rgb, 1 ⇄ alpha, 2 ⇄ xy.

`rgba`, `rgb` and `alpha` are always present. A colour channel the stream lacks reads as zero. `xy` is present only for the XY layout.

The change is a clean break with old projects, with no alias. Colour layer values in old projects reset to `rgba` with a warning, and loading must never crash.

## Rulings settled during implementation

- **A missing colour channel reads zero everywhere.** Every implicit conversion from the colour plane zero-fills the channels the source lacks: RGB→RGBA gives A = 0, Alpha→RGB/RGBA gives RGB = 0 (alpha is not replicated), XY→RGBA gives B = A = 0. This covers ordinary plug-in conversion too (a JPEG into Merge's A input reads A = 0), and identity nodes: an identity Grade on `rgba` over RGB outputs A = 0. Non-colour planes keep the old fill, because a 1-channel plane such as depth reaches a plug-in through an RGBA clip and is read back from channel 0. (User, UAT round 1, 2026-09-28: clean break, don't preserve the old A = 1.)
- **A node's output channels are its input's channels plus the ones it writes.** The stored layout is the narrowest of Alpha/XY/RGB/RGBA covering both, so alpha-only into Grade on `alpha` stays alpha-only, and RGB into Grade on `alpha` becomes RGBA with RGB passed through untouched. `All` and regex rows write only what is present, so a default-All Blur leaves an RGB JPEG as RGB. A plug-in whose clip can't take that layout renders into a wider one and the host narrows the result back. Merge of two RGB inputs outputs RGBA with alpha 0 (Merge's default is a full `rgba` row). Writers never widen. (User, 2026-09-29.)
- **Natron's pickers replace plug-in layer and channel menus.** Where an OFX plug-in owns a plane or channel choice (Premult, Unpremult, IDistort, STMap, and any plug-in built on the same multiplane library), a native layer or channel picker takes its place and pushes its value into the hidden plug-in choice. The plane picker is labelled "Layer" and its "All" entry replaces the plug-in's All Planes checkbox. A channel picker lists each colour channel once, under the view matching the stream's layout (`rgba.*`, `rgb.*`, or a single `alpha`), because the views alias one plane. This mirrors Nuke, whose OFX bridge never names layers to plug-ins. (User, 2026-09-29/30.)
- **Plug-ins take alpha-only streams.** Our openfx-supportext, openfx-misc, openfx-io and openfx-arena forks read a missing colour channel as 0 rather than 1, and 13 plug-ins (Grade, Premult, ReadPNG/WritePNG and others) accept alpha-only clips. The remaining RGBA-only plug-ins go through the host fallback above.
- **Shuffle.** Reading a colour channel the input lacks gives 0 with no error. A missing non-colour layer or channel still fails the render. Implicit sources between colour views wire by colour bit (so `alpha` reads rgba's A). The colour output keeps the main input's layout when that covers what it writes, otherwise it is RGBA. Overlapping output views make Out 2 count as None; disjoint views merge into one plane.
- **Clean break.** On load, any layer value naming the old storage ID becomes `rgba` with its channels kept, and each affected node gets one warning: "Colour layer from an older project was reset to rgba". Natron ≤ 2.2 colour choice options are no longer rewritten. Python layer setters raise `ValueError` on the old ID. Third-party scripts that hard-code `uk.co.thefoundry.OfxImagePlaneColour` must switch to a view name.

Implemented by M65; M37 stacks on it.
