# OCIO is a project property and the only colour pipeline

2026-10-02, M50 (user scope: full replacement; answers Q1–Q3 and the missing-colourspace call).

- **The project owns the config.** Each project saves an OCIO config. It is a built-in `ocio://` URI or a custom file, and defaults to ACES 2.0 Studio. It also saves a working space (default: the `scene_linear` role, ACEScg), per-file-type default colourspaces, and the default viewer display and view, all on a new project "Color" page. The LUT page and Natron's built-in sRGB/Rec.709/BT1886/Linear LUTs are gone.
- **The `OCIO` env var overrides it, Nuke-style (Q1).** A set `OCIO` forces the config for every project, new or loaded, and disables the project's config knobs. The saved value stays in the file and comes back when the variable is unset. The preference "Default OpenColorIO config for new projects" seeds new projects. Natron exports `OCIO` at startup with a marker (`NATRON_OCIO_ENV_IS_PREFERENCE`), so its own background renders don't read that export as a user override. There is no more restart dialog.
- **Bit depth is storage, not colour (Q2).** Integer↔float conversion is plain linear quantisation: scale, clamp, round, with no transform and no dither. A colourspace change at an integer-only stage is explicit: the user converts beforehand, or the plugin offers its own option. No shipped plugin is integer-only.
- **Per-file-type defaults (Q3).** 8-bit and 16-bit use "sRGB Encoded Rec.709 (sRGB)", log uses ACEScct, and float uses ACEScg, so float EXRs read with no conversion. PNG output is labelled scene-referred; the pixels are identical to the earlier display-referred label. These defaults apply only to *new* Reads and Writes. Changing a project default never edits existing nodes.
- **Plugin contract.** The host answers `kOfxImageEffectPropOCIOConfig` (ASWF `ofxColour.h`), plus Natron props for the working space and the four file colourspaces. It also pushes the config into each OCIO node's hidden `ocioConfigFile` param with a plugin-edit reason, and that push is the change channel. The openfx-io and openfx-arena forks read the host config per instance.
- **Unresolved colourspaces flag an error (user).** On a config switch, a node whose colourspace the new config lacks keeps the name and shows a persistent error until it is fixed or switched back. Nothing is remapped silently.
- **Viewer.** Each viewer has Display/View/Look menus, seeded from the project defaults and saved with the viewer. The pipeline is OCIO's look and display/view only, with Natron's gain, offset and gamma around it. The 32f path uses an OCIO-generated GLSL shader. The 8-bit path uses a checked shaper+3D LUT (within 1 code value) that falls back to the exact processor. Swatches, the colour selector, the picker and the tracker overlay go working → `color_picking`. Node previews use the default display/view.
- **Clean break.** Old projects' LUT settings and old viewer state are not imported, and the legacy OCIO fixture is deleted.
