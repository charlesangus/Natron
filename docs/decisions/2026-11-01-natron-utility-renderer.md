# 2026-11-01 — Natron Utility renderer

Natron gets its own Hydra render delegate, **Natron Utility** (plug-in id `HdNatronUtilityRendererPlugin`), a ScanlineRender-class utility renderer in its own epic, E19 - Utility Renderer (M279–M290). Decided with the user in a `/cat-plan` grill on 2026-11-01:

- **Architecture:** a wavefront ray tracer (ray generation, intersection, shading as separate stages). Shading, sampling and AOV code is written once in Slang and compiled to SPIR-V and to C++; only intersection differs — Vulkan `VK_KHR_ray_query` on the GPU, Embree 4 on the CPU. This departs, for this renderer only, from 2026-10-10-gpu-compute-backend-chosen's rule that CPU fallbacks are hand-written native C++ and the Slang C++ twin is only a test oracle (user). Rationale: Slang's cpp target has no ray queries, so a wavefront split is the only way to share shading, and one shading implementation avoids CPU/GPU drift.
- **Devices:** GPU when the engine's `GpuDevice` has ray query and acceleration structures, else CPU; GPUs without ray-tracing hardware fall back to CPU (no compute-shader BVH). A `Device: Auto / GPU / CPU` setting overrides; forced GPU where unavailable is a node error; in Auto a GPU out-of-memory re-renders that frame on CPU with a warning. GPU output stays resident for downstream GPU nodes (2026-10-10-gpu-residency-from-day-one).
- **Features:** UsdPreviewSurface plus USD lights (all UsdLux types, shaping/IES, light and shadow linking) with ray-traced shadows (tinted through transmissive surfaces); ray-traced reflection and refraction, no GI or caustics; native evaluation of USDProject3D's projection; multi-sample antialiasing and true motion blur (shutter from the camera, overridable); OpenSubdiv subdivision at a setting/primvar level (screen-space adaptive dicing and displacement are later stubs); spherical, cylindrical and UV-unwrap projections; data, lighting-lobe, light-group and Cryptomatte AOVs; deep output with user-controlled compaction.
- **Unknown materials render magenta** with one node warning; a scene with no lights is unlit (emission only).
- **AOVs reach USDRender through M256 - Delegate AOV Selection**, of which Natron Utility is the first full client.
- **Deep transport is settled by M286 - Utility Renderer Deep Output**: a delegate's deep result leaves through a custom `HdRenderBuffer` resource that the host turns into a `DeepImage` — no file, no extra process. M255 - Delegate Output Spikes' deep spike then only asks whether Cycles and MoonRay can fill that buffer.
- **Default:** once M285 - Utility Renderer AOVs lands, a new USDRender defaults to Natron Utility; the 3D viewer stays on Storm (M248's decision unchanged). Its plugInfo priority stays above 0 so Hydra's own default remains Storm.
